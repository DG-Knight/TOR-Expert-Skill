# ขั้นตอนร่างและตรวจ TOR

## การจำแนกงาน

ตรวจผลลัพธ์หลัก สัดส่วนสินค้า/บริการ การออกแบบ การผลิต การดัดแปลง การติดตั้ง ฐานราก โครงสร้าง ระบบ สาธารณูปโภค IT/SaaS/License กรรมสิทธิ์ ราคากลาง แบบสัญญา คุณสมบัติ และวิธีตรวจรับ หากชื่อโครงการไม่สอดคล้องกับเนื้อแท้ให้แจ้ง Red Flag

## สายโซ่ข้อกำหนด

เชื่อม ความจำเป็น → วัตถุประสงค์ → ผลลัพธ์ → Performance/Functional Requirement → คุณสมบัติ → Scope → Deliverables → การตรวจรับ → ระยะเวลา → งวดงาน/เงิน → Warranty/SLA → ค่าปรับ → การเปลี่ยนแปลงและขยายเวลา

## การตรวจ Spec Lock

ตรวจ Direct, Datasheet, Numerical, Certification, Dealer, Experience, Personnel, Geographic, Compatibility, POC/Demo, Scoring, Ecosystem และ Bundling lock พร้อมถามว่าข้อจำกัดจำเป็นและได้สัดส่วนกับผลลัพธ์หรือไม่

## มุมมองผู้มีส่วนเกี่ยวข้อง

วิเคราะห์จากมุมหน่วยงาน ผู้ประกอบการ คณะกรรมการ TOR คณะกรรมการพิจารณาผล คณะกรรมการตรวจรับ ผู้ควบคุมงาน ผู้ตรวจสอบ สตง. ป.ป.ช. และคณะกรรมการพิจารณาอุทธรณ์

## Appeal Risk Test

ตรวจว่าข้อกำหนดมีฐานความจำเป็นและได้สัดส่วนหรือไม่ เปิดเผยล่วงหน้าอย่างเท่าเทียมหรือไม่ หลักฐานและเกณฑ์ตัดสินชัดเจนหรือไม่ และข้อใดอาจทำให้ผู้ยื่นข้อเสนอเสียสิทธิ ถูกตัดสิทธิ หรือมีเหตุอุทธรณ์

## Integrity Risk Test

ตรวจผลประโยชน์ทับซ้อน การแบ่งหน้าที่ การใช้ดุลพินิจที่ไม่มีหลักฐาน การกำหนดผู้ผลิตหรือผู้รับจ้างโดยอ้อม การเปลี่ยนเงื่อนไขหลังประกาศ และช่องว่างในการตรวจรับหรือบริหารสัญญาที่เอื้อประโยชน์เฉพาะราย

## งาน IT และบริการดิจิทัล

ตรวจ IP, PDPA, Cybersecurity, API, Source Code, Data Portability, Exit Plan, License, SLA, การสำรองและคืนข้อมูล และ Vendor Lock-in ทุกครั้ง กำหนดเจ้าของข้อมูล รูปแบบส่งคืนข้อมูล ระยะเวลาส่งมอบ และวิธีทดสอบการย้ายออกจากผู้ให้บริการ
