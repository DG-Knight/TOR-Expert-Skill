# แบบออกแบบแพ็กเกจ TOR งานภาครัฐ Expert

## เป้าหมาย

สร้างผู้ช่วย TOR งานภาครัฐขึ้นใหม่จากศูนย์ให้พร้อมใช้ทั้ง ChatGPT Plugin และ Gemini CLI Agent Skill โดยใช้คำสั่งและคลังความรู้แกนกลางร่วมกัน พร้อมดาวน์โหลดเอกสารต้นทางจากหน่วยงานราชการ ตรวจสอบไฟล์ และแยกสถานะเอกสารปัจจุบันออกจากเอกสารเก่าอย่างชัดเจน

## ขอบเขตส่งมอบ

1. Plugin แบบ Skills-only สำหรับ ChatGPT/Codex ตามโครงสร้าง Agent Plugins ปัจจุบัน
2. Gemini CLI Agent Skill ที่ติดตั้งหรือเชื่อมเข้า `.gemini/skills/` ได้
3. คำสั่งหลักภาษาไทยสำหรับร่าง ตรวจ และวิเคราะห์ TOR
4. คลังเอกสารกฎหมายและหนังสือเวียนที่ดาวน์โหลดจากแหล่งราชการต้นทางเท่าที่ตรวจสอบได้
5. ทะเบียนเอกสารที่ระบุชื่อ เลขที่ วันที่ แหล่งที่มา ค่าแฮช และสถานะการใช้งาน
6. เขตแยกเอกสารที่ถูกยกเลิก ถูกแทนที่ หรือยังยืนยันสถานะไม่ได้
7. ชุดทดสอบโครงสร้าง แหล่งอ้างอิง และพฤติกรรมสำคัญของ Skill
8. เอกสารกลาง `docs/implementation-plan.md`, `docs/task.md`, `docs/walkthrough.md` และ `docs/changelog.md`

## สถาปัตยกรรม

ใช้โฟลเดอร์ Plugin เป็นแหล่งจริงเพียงชุดเดียว โดย Skill หลักเก็บขั้นตอนทำงานใน `SKILL.md` และแยกเนื้อหารายละเอียดไว้ใน `references/` เพื่อลดการใช้บริบทโดยไม่จำเป็น ฝั่ง Gemini ใช้แพ็กเกจ Skill รูปแบบเดียวกันและมีสคริปต์ติดตั้งที่คัดลอกไฟล์จากต้นฉบับ จึงไม่ต้องดูแลคำสั่งซ้ำสองชุด

```text
tor-expert/
├── plugin.json
├── skills/tor-government-expert/
│   ├── SKILL.md
│   ├── references/
│   └── assets/
├── knowledge/
│   ├── 01_LEGAL_CORE/
│   ├── 02_CURRENT_CIRCULARS/
│   ├── 03_SPECIAL_RULES/
│   ├── 04_PRACTICAL_REFERENCE/
│   ├── 90_PENDING_VERIFICATION/
│   └── 99_ARCHIVE_SUPERSEDED/
├── gemini/
├── scripts/
├── tests/
└── docs/
```

## การไหลของข้อมูล

1. ดาวน์โหลดจาก URL ต้นทางที่บันทึกไว้ในทะเบียนเท่านั้น
2. ตรวจชนิดไฟล์ ลายเซ็น PDF จำนวนหน้า ข้อความตัวอย่าง และ SHA-256
3. จัดเอกสารเข้าโฟลเดอร์ตามสถานะที่ยืนยันได้
4. Skill อ่านทะเบียนก่อนเลือกเอกสาร และห้ามใช้ไฟล์ใน `90_PENDING_VERIFICATION` หรือ `99_ARCHIVE_SUPERSEDED` เป็นหลักฐานกฎหมายปัจจุบัน
5. คำตอบต้องแยกข้อเท็จจริง หลักเกณฑ์ การวิเคราะห์ และข้อเสนอแนะ พร้อมระบุเมื่อข้อมูลยังไม่เพียงพอ

## หลักความปลอดภัยและความถูกต้อง

- ไม่คัดลอกหรืออ้าง system/developer prompt ลับของแพลตฟอร์ม
- ไม่ถือข้อสรุปในแชทเดิมเป็นข้อเท็จจริงทางกฎหมายจนกว่าจะตรวจจากแหล่งราชการ
- ไม่อ้างว่าเอกสารเป็นฉบับล่าสุดหากยังไม่มีหลักฐานยืนยัน
- ไม่รวมรหัสผ่าน คีย์ หรือข้อมูลลับไว้ในแพ็กเกจ
- เอกสารที่ดาวน์โหลดไม่ได้หรือมีหลักฐานขัดแย้งต้องถูกพักไว้พร้อมเหตุผล

## การทดสอบ

- ตรวจ manifest และโครงสร้าง Skill ของทั้งสองแพลตฟอร์ม
- ตรวจว่าเอกสารทุกไฟล์ในทะเบียนมีอยู่จริงและค่าแฮชตรงกัน
- ตรวจว่าไฟล์ PDF เปิดได้ มีอย่างน้อยหนึ่งหน้า และไม่ใช่ HTML ที่เปลี่ยนนามสกุล
- ตรวจว่าเอกสารสถานะเก่า/รอตรวจไม่ถูกจัดอยู่ในคลังปัจจุบัน
- ทดสอบคำขอที่ควรเรียก Skill, ไม่ควรเรียก Skill, ข้อมูลไม่ครบ และคำถามที่เสี่ยงต่อการเดาข้อกฎหมาย

## เกณฑ์เสร็จสมบูรณ์

งานเสร็จเมื่อแพ็กเกจผ่านการตรวจอัตโนมัติทั้งหมด สามารถติดตั้ง Skill ใน Gemini CLI จากไฟล์ที่สร้างได้ Plugin มี manifest ถูกต้อง เอกสารที่หาได้ถูกดาวน์โหลดและตรวจสอบแล้ว เอกสารที่ยังหาไม่ได้แสดงเป็นรายการค้างอย่างตรงไปตรงมา และมี Git commit ของงานทั้งหมด
